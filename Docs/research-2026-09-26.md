# ArenaRegen Update Research — 2026-09-26

## Product Summary
ArenaRegen is a Minecraft Spigot/Paper plugin that captures and regenerates arena regions without WorldEdit dependency. It provides dual-build packaging:
- **MODERN**: Paper 26.2 (NMS fast block setting, Java 25)
- **LEGACY**: Bukkit API for 1.18–1.21.x (Java 17+)

Current version: 1.7.1 (released 2026-09-25).

---

## Candidate Ideas

## ID: arenaregen-01 — Multiverse World Loading Fix & /arenaregen reloadarenas

Problem: Arenas in Multiverse worlds can fail to load on server restart because Multiverse-Core loads after ArenaRegen. When world is not found, arena is deferred, but server owners see "no arenas found" and have no command to reload without restarting the server.
Evidence: Recorded in `Docs/bug_tracking.md` (2025-08-14). `plugin.yml` currently omits `Multiverse-Core` from `softdepend`.
Already supported? Plugin contains deferred loading logic in `RegionData.java`, but lacks `Multiverse-Core` load order and has no reload command for arena files.
Suggested change: Add `Multiverse-Core` to `softdepend` in `plugin.yml`. Add `/arenaregen reloadarenas` command to reload all `.datc` files from disk on demand.
Expected benefit: Arenas in secondary worlds load reliably on reboot. Server owners can reload arenas without rebooting.
Size: Small
Risk and later support work: Low risk. Local change to `plugin.yml`, `ArenaRegenCommand.java`, and `ArenaRegen.java`.
Why this rank: Rank 1. Resolves confirmed data access issue and completes unfinished recovery workflow.
First release: Add softdepend, add `/ar reloadarenas` with success and failure summary counts.
Unknown: None.

## ID: arenaregen-02 — Container Inventory and State Preservation (Chests & Barrels)

Problem: Arenas containing chests, barrels, dispensers, or furnaces lose their inventory contents after regeneration. All containers reset to empty blocks.
Evidence: Code review of `RegionData.java` shows banner and sign preservation, but zero container serialization. Unmerged prototype handlers exist in `helpers/tileentity/handlers/ChestHandler.java`. Server owners on practice/minigame servers expect loot chests to restore.
Already supported? Plugin restores banners and signs. Containers are restored as empty blocks.
Suggested change: Serialize container block state and inventories during arena creation. Restore inventories when blocks regenerate.
Expected benefit: Arenas with kits or loot chests (hunger games, duels, practice) reset with original items intact.
Size: Medium
Risk and later support work: Requires file format version migration or backwards-compatible section in `.datc`.
Why this rank: Rank 2. High functional value for server owners running PvP and minigames.
First release: Support standard Chests, Trapped Chests, Barrels, and Shulker Boxes.
Unknown: Serialization compatibility across Bukkit versions.

## ID: arenaregen-03 — WorldEdit / FAWE Selection Integration

Problem: Server owners must use `/arenaregen wand` and click physical blocks to select arena corners. Selecting boundaries in the air or across large builds is difficult.
Evidence: Common practice across competing plugins (FastArena, oArenas). Builders already create regions using WorldEdit `//wand` or `//pos1` and `//pos2`.
Already supported? Golden hoe wand tool only.
Suggested change: Add optional WorldEdit hook. If WorldEdit is present and player has an active selection, allow `/arenaregen create <arena>` to use the WorldEdit selection automatically.
Expected benefit: Faster arena creation and setup with zero scaffolding needed.
Size: Small
Risk and later support work: Low risk. Optional soft-dependency check.
Why this rank: Rank 3. Reduces friction during initial plugin setup.
First release: Detect WorldEdit selection as fallback when no golden hoe points are set.
Unknown: WorldEdit 7 API nuances between Spigot and Paper.

## ID: arenaregen-04 — Post-Regen Residual Dropped Items Clean-Up

Problem: Blocks that break during regeneration (such as unsupported torches, lanterns, doors, or falling sand) drop as floating items on the ground and stay in the arena.
Evidence: Code review of `ArenaRegen.java` shows entity removal occurs only before block setting starts (line 1011). Blocks that detach during setting drop new `Item` entities.
Already supported? Pre-regeneration entity removal exists when `track-entities: true`.
Suggested change: Execute a cleanup pass for dropped `Item` entities in the arena bounding box when regeneration completes.
Expected benefit: Clean arena floor with no dropped item debris after reset.
Size: Small
Risk and later support work: Very low risk. Simple entity filter on primary thread.
Why this rank: Rank 4. Visual and mechanical polish for every reset.
First release: Clear dropped items within bounding box after chunk relighting completes.
Unknown: None.

## ID: arenaregen-05 — Schedule Overview Command (/arenaregen schedule list)

Problem: Server owners cannot view a list of all active regeneration schedules or next run times from in-game commands.
Evidence: `ArenaRegenCommand.java` allows `/ar schedule <arena> [time]` and `/ar info <arena>`, but provides no overview of all active schedules.
Already supported? Schedules run and save to `schedules.yml`, and PlaceholderAPI supports `%arenaregen_nextregen_<arena>%`.
Suggested change: Add `/arenaregen schedule list` (or `/arenaregen schedules`) to display all configured schedules, intervals, and time remaining until the next reset.
Expected benefit: Easy administration and monitoring of scheduled arena resets.
Size: Small
Risk and later support work: Very low risk. Read-only command feature.
Why this rank: Rank 5. Convenience feature for multi-arena servers.
First release: `/arenaregen schedule list` showing table of arena, interval, and next run time.
Unknown: None.
